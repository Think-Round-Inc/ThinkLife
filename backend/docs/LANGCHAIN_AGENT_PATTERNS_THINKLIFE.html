## 2) Pattern 1: ReAct (Reason + Act)


## What it is

ReAct alternates between:

1. reasoning about next action,

2. executing a tool/data action,

3. observing result,

4. repeating until final answer.


## What ThinkLife already has for ReAct

ThinkLife has reusable pieces:


```python

# backend/brain/cortex/reasoning_engine.py

    ...

    return self._parse_decision(response.get("content", ""))

```


Source: `backend/brain/cortex/reasoning_engine.py:35`

    if "tool" in resp: return {"action": "use_tool", ...}

    if "data" in resp or "search" in resp: return {"action": "query_data", ...}

    if "complete" in resp or "done" in resp: return {"action": "complete", ...}

## Production multi-agent use case

- **Best for**: dynamic retrieval/search-heavy tasks where agent must iteratively decide next step (research, support triage, incident investigation).

- **In ThinkLife**: a “Research Agent” could repeatedly query Tavily + vector DB until confidence is acceptable, then handoff final result to a “Care Response Agent.”

## 4) Pattern 3: Self-Ask


## What it is

Self-Ask decomposes one user question into sub-questions, answers each sub-question (possibly with tools), then synthesizes final answer.


## ThinkLife pieces that can support Self-Ask

- Iterative refinement hooks:


```python

# backend/brain/cortex/reasoning_engine.py

async def refine_plan(...):

    # continue / try different tools / conclude

```


Source: `backend/brain/cortex/reasoning_engine.py:98`


- Validation-driven retry loop:


```python

# backend/brain/cortex/workflow_engine.py

while True:

    state = await self._build_messages_node(state)

    state = await self._call_provider_node(state)

    state = await self._validate_response_node(state)

    route = self._route_after_validation(state)

    if route == "finalize":

        break

```


Source: `backend/brain/cortex/workflow_engine.py:241`


## Current gap

No explicit `subquestions[]` state in `WorkflowState` yet, and no dedicated “decompose -> solve -> synthesize” nodes.


## Production multi-agent use case

- **Best for**: complex advisory questions requiring decomposition (e.g., “Compare treatment options, risks, and practical steps for my context”).

- **In ThinkLife**: one “Decomposer Agent” can create sub-questions, specialist agents answer each, and a synthesis agent produces trauma-informed final output.

## 6) Practical recommendation for ThinkLife roadmap


1. Keep **Plan-and-Execute** as default for safety-critical flows (already production-ready shape).

2. Add **ReAct mode** for research/ops agents by wiring real tool execution in `_execute_tools_node`.

3. Add **Self-Ask mode** by extending `WorkflowState` with `subquestions`, adding nodes:

   - `decompose_question`

   - `answer_subquestion`

   - `synthesize_answer`

4. Use `adaptive` planning strategy as default in new agents to combine speed + robustness.
